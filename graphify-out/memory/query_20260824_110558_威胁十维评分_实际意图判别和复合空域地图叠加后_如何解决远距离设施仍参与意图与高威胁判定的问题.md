# Q: 威胁十维评分、实际意图判别和复合空域地图叠加后，如何解决远距离设施仍参与意图与高威胁判定的问题

## Answer

用户业务真值是每个data.list[i]构成独立空域单元，三级半径countermeasureRadius/alertRadius/warningRadius都以该记录原始facilityList[0]为中心；复合地图仅是多个空域单元的并集。当前实现有三处偏差：default_map_refresh会过滤无效设施后取第一个有效设施而非严格原始第一个；zoneType=2时优先使用Geom而非始终使用半径；所有设施扁平化后engine._nearest_facility无条件选择全局最近设施。另有架构重复：集群意图威胁先通过engine._ring_status/_nearest_facility评分，targetAirspaceResults却在评分后由AirspaceRelationAnalyzer独立计算，后者已有5000米airspaceAssessmentRangeMeters但无法约束前者。应先构造带airspaceId、anchorFacilityId、三级ring和maxRadius的AirspaceUnit；原始首设施无效时跳过整条空域并告警，不得换第二个；其他设施可保留展示但不能替代圈层锚点。随后在评分前为每目标只计算一次SpatialContext：优先选择实际命中的最高级圈层，未命中时仅在warning边界加airspaceAssessmentRangeMeters范围内关联最近空域，仍无候选则airspaceId/facilityId为空、spatialRelevant=false。接近趋势必须固定对同一个anchorFacility计算，不能前后点分别选全局最近设施。Intent和Threat共用SpatialContext：非空间意图可独立判定，设施/圈层意图必须spatialRelevant且绑定同一airspaceId；I-26增加最大距离和同一相关空域限制。威胁保持十维基分，但将硬规则分为全局证据和空间证据：确认释放/武器可全局高威胁；普通转向不再全局触发66，legacy turning需统一到120度并要求持续证据，空间型R5/R8/R9/R7必须通过相关性门控。最终分可写为S_final=max(S_base,F_global,F_spatial)。同一SpatialContext同时生成targetAirspaceResults、cluster airspaceId、意图特征、威胁和affectedFacilities，彻底消除双路径不一致。兼容接口可新增spatialRelevant与threatScope；最佳长期方案是区分overall/behavior threat与facility threat。
