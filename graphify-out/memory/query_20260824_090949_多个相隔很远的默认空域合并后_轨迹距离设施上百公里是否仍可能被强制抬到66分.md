# Q: 多个相隔很远的默认空域合并后，轨迹距离设施上百公里是否仍可能被强制抬到66分

## Answer

会，而且已用 tester_real_v32_replay_bundle_20260822_102936.json 的同一轨迹验证。将请求地图模拟为仅保留北京设施、无圈层时，轨迹到最近设施约1162567米，zoneTier=outside，intentCode为空，但threatScore=66、hardRuleFloor=66。直接命中R6：engine._threat把 heading_change>=120 或 legacyBehavior.turning 或 releaseEvent 任一条件当作规避/俯冲/释放行为并强制下限66，R6没有设施距离和圈层条件。该样本releaseEvent=false，当前运动窗口headingChangeDegrees约7.263，但旧行为提取器在最多8段窗口内计算累计转向40.572度；config.ini旧阈值仅20度，所以legacy turning=true，随后被R6当成高危规避。远距离空域本身不会产生圈层误命中，因为圈层按点落入几何判断；问题在于全局最近设施始终会被选中，以及R6不看空间关系。另一个潜在风险是I-26多机同步抵近没有最大设施距离约束，命中后R7同样强制66。建议取消legacy turning对R6的直接触发或统一到120度并增加持续性证据；将普通转向硬规则限定在相关空域/设施作用半径内；releaseEvent等确证危险行为可保留全局高威胁；给I-26增加最大距离；超出地图相关半径时nearestFacilityId应为空或标为不相关，并区分平台行为威胁与对设施威胁。
