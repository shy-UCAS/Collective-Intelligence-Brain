# 一、全篇统一口径

## 1. 汇报目标

本 PPT 不以研发过程为主线，而是向客户说明：

```text
系统如何从多源观测中形成可计算证据；
不同意图为什么需要不同专家进行判断；
单机行为、群体结构和感知事件如何联合推理；
系统如何输出主意图、候选意图、触发成员和证据链；
算法如何通过数据、知识和评测闭环持续迭代。
```

## 2. 统一表达原则

- 面向 I-01～I-30 展示完整的意图识别技术体系。
- 不在客户可见页面区分“当前方法”和“后续方法”，各专家统一展示完整技术路线。
- 不把 30 类意图描述成 30 套彼此隔离的算法，而是组织为统一证据底座上的五类专项专家。
- 不用模型名称堆叠创新，重点展示数据如何流动、证据如何形成、约束如何生效、结论如何输出。
- 每页只承担一个叙事职责，避免重复出现相同的“输入—处理—输出”说明。
- 客户可见内容不出现内部状态、研发批注、待办事项和验收缺口。

## 3. 全篇统一技术主线

```text
多源观测
    ↓
时空对齐与目标关联
    ↓
统一意图证据帧
    ↓
五类专项专家
    ↓
可靠性门控与可信融合
    ↓
主意图、候选意图、触发成员与证据链
```

## 4. 专家体系

```text
业务、身份与合规专家
轨迹与 GIS 时序专家
群体结构与协同专家
  ├─ 群体结构识别
  └─ 群体协同意图识别
多模态事件与平台状态专家
开放集异常与可靠性专家
```

所有专家之后连接“统一可信融合中枢”。融合中枢负责候选标准化、证据聚合、冲突约束、可信度校准、主意图选择和拒识复核，不作为第六类意图专家。

## P2｜从发现目标，到理解它为什么这样飞

### 页面主张

态势感知的价值不止是发现目标，更重要的是理解行为目的并支撑决策。

### 页面文字

```text
感知层：目标在哪里、如何运动？
认知层：目标正在执行什么行为？
研判层：为什么这样判断、结论是否可信？
决策层：是否需要持续跟踪、人工复核或处置？
```

底部结论：

> 单纯的位置、速度和轨迹无法直接回答目标意图。

### 配图说明

使用一条由“点迹发现 → 航迹形成 → 行为理解 → 意图研判 → 决策支撑”组成的视觉路径。本页不展开系统输入、专家结构和输出字段，与 P6 的技术架构页保持区分。

## P3｜同一场景中，多种行为和意图可能同时存在

### 页面主张

真实空域不是单目标、单行为、单结论场景，而是多目标、多关系、多意图并存。

### 页面文字

一个复杂场景可能同时包含：

```text
合法巡检目标沿计划航线飞行
未报备目标在重点区域附近悬停
多个目标同步向同一设施接近
部分目标身份或载荷信息异常
目标在不同时刻进入不同防护圈层
```

需要同时理解：

```text
目标级行为｜群体级关系｜业务级约束｜时空环境上下文｜多源感知事件
```

### 配图说明

使用一张俯视态势地图，表现合法计划飞行、多机同步抵近、设施附近绕飞或悬停、身份信息不完整，以及设施、禁飞区和多层防护圈。右侧只保留一句话：

> 同一场景，需要并行理解多个目标、多个群体和多个候选意图。

## P4｜意图识别面临四类核心难题

### 页面主张

意图识别不是单点分类，而是对时序、多源、关系和不确定性证据的综合判读。

### 页面文字

#### 观测不完整

```text
轨迹可能缺失、重复、延迟或存在噪声；
身份、计划、载荷和环境证据可能不可用。
```

#### 行为同形异意

```text
同样的悬停可能对应设备调试、景点航拍或要地侦察；
同样的偏航可能来自故障、风场或人为操纵。
```

#### 个体与群体耦合

```text
单机行为不能完全解释群体协同；
群体结构又会改变单机行为的业务含义。
```

#### 多候选竞争

```text
夜间飞行、圈层闯入、身份异常和攻击行为可能同时成立；
系统需要保留候选、处理冲突并表达不确定性。
```

### 配图说明

用断裂轨迹、相同轨迹对应不同意图、多机关系图和多个候选汇聚，分别表现四类难题。

```text
→ 轨迹行为与感知事件一致性校验
→ 事件持续性、强度和可靠度评估
→ 载荷、干扰与平台状态类意图候选
```

#### 模态分工

```text
雷达：运动状态、目标数量和散射变化
光电/红外：载荷、朝向、释放和外观变化
RF：遥控链路、频谱异常和干扰行为
GNSS：定位质量、欺骗、漂移和失锁
环境：风场、天气及外部运动影响
```

#### 代表意图

```text
I-06、I-07、I-09、I-19、I-23、I-25、I-27
```

### 配图说明

五类传感器输入先分别形成结构化事件，再汇入事件—目标关联和跨模态证据融合，最终与轨迹行为进行一致性校验。

## P14｜可信研判先判断证据是否可用，再融合多个意图假设

### 页面主张

系统不是把多个专家结果简单排序，而是联合考虑可观测性、证据一致性、意图关系和不确定性。

### 页面文字

#### 开放集异常与可靠性门控

```text
数据质量与来源状态汇总
→ 逐意图证据需求检查
→ 可观测性与证据覆盖度评估
→ 缺失、冲突、异常和分布漂移检测
→ 已知意图模式兼容性分析
→ 未知行为与变化点识别
→ 不确定性分解与可信度校准
→ 接受、降级、拒识或人工复核
```

#### 统一可信融合中枢

```text
多专家候选接入
→ 候选字段与置信尺度统一
→ 可观测性和数据质量加权
→ 同类候选的跨专家证据聚合
→ 支持证据与矛盾证据联合分析
→ 意图互斥、并存和上下位关系约束
→ 跨时间候选持续性校验
→ 可信度和不确定性校准
→ 主意图、并发候选或拒识决策
```

#### 最终输出

```text
主意图与完整候选集合
实际触发目标与关联设施
支持证据与矛盾证据
可信度、不确定性和人工复核状态
```

### 配图说明

从左到右画“可靠性门控 → 多专家候选与证据 → 可信融合和结果输出”。排序规则只作为融合中枢内部最后一步，不作为本页核心创新。

## P15｜数据、知识与评测闭环驱动算法持续进化

### 页面主张

意图识别能力的持续提升，依赖统一数据、知识管理、离线评测和困难样本回流形成闭环。

### 页面文字

```text
真实数据、仿真数据与历史案例
→ 统一标注与意图知识组织
→ 规则、特征和模型开发
→ 离线回放与多维指标评测
→ 接口联调与场景验证
→ 人工复核与结果审计
→ 困难样本回流
→ 新版本受控发布
```

#### 闭环管理内容

```text
意图编码和业务定义
数据来源、标签和适用范围
特征、规则和模型版本
证据链与判断结果
误报、漏报和拒识样本
跨区域、跨设备和跨采样条件表现
```

### 配图说明

使用单一环形闭环，中心写“可回放、可评测、可审计、可迭代”，不再拆分“数据底座”和“工程验证”两页。

## P16｜统一架构让意图识别更早、更准、更可信

### 页面主张

通过统一证据、专项专家、群体认知和可信融合，系统把目标发现提升为可解释的意图研判能力。

### 页面文字

#### 统一证据

```text
30 类意图共享目标、时间、空间、关系和质量语义。
```

#### 专项研判

```text
不同意图按证据结构进入不同专家，不由单一分类器硬判全部行为。
```

#### 群体认知

```text
区分空间聚集、稳定编组、行为同步、共同目标和协同意图。
```

#### 可信决策

```text
保留多个候选、实际触发成员、证据链和不确定性，支撑人工复核与处置。
```

底部总结：

> 从“发现目标”走向“理解行为”，从“给出标签”走向“提供可信决策依据”。

### 配图说明

使用“看得见 → 看得懂 → 判得准 → 说得清”四个递进关键词，不再放研发阶段路线图。

# 五、尚未讨论或解决的问题（仅供内部编制使用，不进入客户 PPT）

## P0｜在继续制作 PPT 前需要解决

1. **各专家的具体算法材料尚未补充。** 当前已确定模块级技术架构，但每个阶段采用的具体模型、特征、公式、训练方式和推理方式仍需根据后续材料展开。

2. **30 类意图的主专家与辅助专家映射需要逐项复核。** 特别需要确认 I-04、I-06、I-07、I-09、I-20、I-27、I-28、I-29 等跨业务、轨迹、环境或开放集证据的意图归属。

3. **多专家可信融合的具体实现路线尚未确定。** 需要进一步明确可观测性门控、置信尺度统一、证据聚合、意图关系图、时间持续性、不确定性校准和拒识策略分别采用什么方法。

4. **开放集专家与 I-28 的技术关系尚需单独讨论。** 需要明确未知行为检测、异常变化、已知类别拒识和具体 I-28 候选之间的边界。

5. **客户版技术口径需要内部确认。** 当前脚本按完整专家技术路线呈现，不展示研发阶段差异；仍需由产品、算法和项目负责人共同确认最终对外措辞及现场问答边界。

## P1｜影响页面内容深度的问题

6. **群体结构与协同意图的详细算法仍需补充。** 需要明确动态邻接关系、集群持续跟踪、编队识别、成员角色、共同目标、交互关系和联合预测等模块的具体实现。

7. **多模态事件专家的输入边界仍需确认。** 需要明确雷达、光电、红外、RF、GNSS和环境数据中哪些进入原始感知处理，哪些以结构化事件形式输入意图系统。

8. **是否在正文增加端到端算法案例尚未决定。** 当前放在附录 C；如果客户更关注算法可解释性，可考虑将其提升为正文页面，并相应压缩 P3 或 P4。

9. **实验和量化证据尚未纳入页面。** 需要确认是否展示典型场景结果、处理时延、稳定性、候选一致性或其他可公开指标，以及这些指标的数据来源和统计口径。

10. **30 类意图能力图谱的正文密度尚需验证。** P5 是否完整展示 30 项，还是只展示八大类并把全量列表放入附录，需要在实际 PPT 排版后决定。

## P2｜进入视觉设计阶段前需要确定

11. **汇报时长和最终页数尚未确认。** 当前版本为 16 页正文；需要根据实际汇报时长决定是否进一步压缩专家页或附录。

12. **视觉风格和模板尚未确定。** 需要确认客户品牌、颜色、字体、页面比例、地图底图、图标来源和是否沿用已有 PPT 模板。

13. **每页可见文字与讲解备注的边界尚未确定。** 当前脚本同时包含页面文案和讲解逻辑，制作 PPT 时需要进一步压缩可见文字，并把技术解释移入演讲备注。

14. **统一页脚和版本信息仍需最终确认。** 当前建议不写具体规则版本；如客户交付规范要求版本标识，需要确定统一的软件、接口或算法版本口径。
