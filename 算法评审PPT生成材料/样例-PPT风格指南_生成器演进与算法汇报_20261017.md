## 1. 视觉规范

**画布与边距**（用户要求充分利用空间，图片为主体）
- 1920×1080；`padding:72px 96px 128px`（内容区宽 1728px，底边到 y=952）。
- 纵向布局：`display:flex; flex-direction:column; gap:18px`。
- 有图的页：图片占画面主体（通常左侧 60%–75% 宽，或整排铺满），文字放侧栏；不要留大片空白。截图可先裁到作业区域再放大。

**字体**（deck.json 的 `faces` 已登记，直接用）
- 标题：`'Noto Serif SC', Georgia, serif`，700。
- 正文：`'Noto Sans SC', Arial, sans-serif`。

**字号阶梯（只用这几档）**
| 用途 | 字号 | 备注 |
|---|---|---|
| 大数字 | 64px | Noto Serif SC 700，卡片窄时只放核心数字 |
| 页标题 h2 | 56px | Noto Serif SC 700，line-height 1.1 |
| 卡片标题 h3 | 30–32px | 700 |
| 副标题 / 链路行 | 26px | |
| 正文、列表、图注、表格、页脚 | 24–26px | 不小于 24px |

**颜色**
| 角色 | 色值 |
|---|---|
| 主背景（浅） | `#F6F5F1` |
| 交替背景 | `#ECEFF1` |
| 卡片底 | `#FBFBF8` |
| 表格斑马行 | `#FBFBF8` / `#F1F2EF` |
| 标题 / 深色 | `#16243A` |
| 正文灰 | `#46536A` |
| 页脚灰 | `#6B7689` |
| 强调橙（眉题、"问题"、"当前"、"局限"） | `#B85A1E`；深底上用 `#F4B98A` |
| 强调青（小标题、意图名、"解决"、结论句、流程箭头） | `#0F6E73` |

背景交替：浅（`#F6F5F1`）与灰（`#ECEFF1`）页交错。

**每页固定元素**
1. 眉题：24px、700、`letter-spacing:4px`、橙色，格式"板块 · 小主题"（如"第三代 · 快速仿真"）。算法部分建议用"算法 · ××"。
2. 页标题：一句话结论，不用"××介绍"这类空标题。
3. 页码：右下角 `position:absolute; right:96px; bottom:48px; width:80px`，24px，页脚灰，右对齐。
4. 页脚说明（可选）：左下角 `left:96px; bottom:48px`，24px 页脚灰，一行以内（用于"示例图来源""已知限制"）。
5. 演讲备注：每页写 `<aside>`，包括讲解要点和可能被追问的问题及答法。

**常用版式（照抄已有页面的写法）**
- 对比表（evo）：深色表头行、斑马行、首列加粗。
- 大图 + 侧栏（gen1 / gen1b / plan）：图白底细描边；侧栏用青色 h3 小标题分段，或有序列表。
- 流程框（sim）：等宽白卡片 + `x-shape arrow-right` 青色箭头，每框"①标题 + 一句说明"。
- 大数字卡片（gen2 / sim）：卡片顶边 6px 色条，橙=问题、青=解决/结果，顶部小标签 + 大数字 + 一两行说明。
- N 图并排（scene）：图白底细描边，下方青色名称 + 一句依据。
- 两卡片对照（design）：每卡一个小标题、两图并排、一句青色结论。
- 三栏卡片 + 底部浅青横条（next）：横条放贯穿性结论。

**图片处理**
- 裁掉图上的英文标题和内部编号，中文图注写在图下或侧栏。
- 图中真实地名一律换成"设施 A / B / C"。
- 图片底色白、细描边；完整图用 `object-fit:contain`，已裁成同比例的放大图可用 `cover`。

## 2. 文字规范

**不出现内部代号。** 对照：
| 不写 | 写成 |
|---|---|
| v0.3 / v0.4 / v0.5 | 第二代（真实飞控仿真）的数据、已冻结的第二代数据 |

| uav_strategy | 第一代：基于 SPADE-BDI 的任务编排式原型（SPADE、BDI 要明确写出） |
| SITL / ArduPilot | 真实飞控软件在环仿真（可括注 ArduCopter） |
| fastsim、m3_r2/m3_r3 | 快速仿真、点质量运动学仿真、转弯修正 |
| M1 / M2 / M3、r1.2 / r1.3 | 实测判定、时刻安排、统一规划器、规划器升级 |
| family / skeleton / episode / draw | 场景组 / 任务骨架 / 一次仿真 / 公共条件抽签 |
| first_edition、R0–R4、P0/P1/P2 补丁 | 第一版可量产生成器、整体验证、几处修复 |
| JEPA、MA-JEPA 等算法代号 | 第一次出现时写中文全称或一句话解释，括号内可附英文缩写 |

**方法要讲清楚。** 每一代都写明"用什么方法"：框架、规划方法、运动仿真原理、校准方式，不能只写结论和数字。算法部分同理：模型结构、输入输出、训练目标都要有。

**措辞原则**
- 标题是结论句，正文是短句，不堆长段落；一页一个核心意思。
- 数字只用有出处的；涉及进度的数字视为"截至汇报日"，结果更新后同步改。
- 还没产出的东西不写具体数量（如"第一版即将量产"，不写"共 X 条"）。
- 局限如实写在页脚或卡片里，一行带过。
- 示例图注明来源（如"示例图来自首版生成器输出，分属不同场景"）。
- 项目性质口径：防御方视角的意图识别研究；抽象合成场景；不控制任何真实无人机。

**算法部分建议的衔接方式**
- 第一页用一句话接上数据部分："有了带标签的轨迹数据，下面讲如何从轨迹得到语言描述。"
- 链路图沿用 sim 页的流程框写法："轨迹 → 编码器 → 桥接模块 → 语言模型 → 描述"。
- 结果页沿用大数字卡片或 evo 的表格；没有结果的部分写成"计划 / 待验证"，不编造指标。
- 说明算法当前用的是已冻结的第二代数据（只能证明链路跑通，不报告意图识别准确率）。
