## 1. 失败教训：为什么不能沿用 39 页稿

### 1.1 现状数据

| 指标 | 当前 39 页稿 | 样例 9 页 | 判断 |
|---|---:|---:|---|
| 幻灯片数 | 39（30 正文 + 9 附录） | 9 | 当前偏长 |
| 形状总数 | 1143 | 160 | 当前平均每页 29 个形状 |
| 文本框 | 1135 | 150 | 当前平均每页 29 个文本框 |
| 图片 | 0 | 16 | 当前完全没有图片 |
| 图表 | 5 | 0 | 当前只有少量图表 |
| 总字数 | 1338 | 346 | 每页字数其实相近 |
| 无标题幻灯片 | 39/39 | 0/9 | 当前没有真正的标题占位 |
| 平均每页字数 | 34.3 | 38.4 | **不是字数问题** |
| 平均每个文本框字数 | 约 1.2 | 约 2.3 | **当前碎片化严重** |

### 1.2 五条教训

1. **不要按文档章节切页。** 当前 39 页像把高保真文档逐节搬上 PPT；新 deck 要按“一次请求的旅程”重组。
2. **不要用大量小文本框拼页面。** 1135 个文本框 / 1338 字，说明页面由短标签和单句碎片组成；新 deck 每页只允许 1 个主图/主表、3–5 个短点、1 个底部横条，公式最多 1–2 个公式条。
3. **不要零图片。** 样例 16 张图承担主要叙事；新 deck 目标 12–16 张图/表，正文至少 10 张。
4. **不要没有标题层级。** 新 deck 每页必须有真正的标题占位或统一标题形状，保证大纲、导航、无障碍可用。
5. **不要把协议字段、历史沿革和完整实验矩阵塞正文，但性能结论与关键公式必须留在正文。** 正文保留“算法怎么做、为什么这样、边界在哪”的支撑细节；24 组逐行数据、参数枚举和复现命令放附录，附录只作现场备用。

### 1.3 可保留的旧稿资产

- 演讲稿的“一次请求旅程”主线；
- 对证据边界的克制，不把测试通过说成准确率；
- 跨度、KD-tree、缓存、路由耗时等已有数据；
- 若干已经写清楚的技术判断。

## 2. 新 deck 的叙事主线

### 2.1 一句话定位

> **从一条轨迹到可解释判断：一次请求里，算法怎样把观测变成证据，再把证据变成判断。**

### 2.2 五幕结构

| 幕 | 页 | 主题 | 观众要记住的事 |
|---|---|---|---|
| 第一幕 | P01–P05 | 输入与事实 | 算法从上游轨迹开始；双窗口、去重、运动特征决定了后面能算什么 |
| 第二幕 | P06–P09 | 分组与队形 | 聚类不是固定半径；队形是点集分类，不是时序模型 |
| 第三幕 | P10–P15 | 空间与判读 | 一个主上下文贯穿意图/威胁；19 条规则有明确的启用边界 |
| 第四幕 | P16–P20 | 评分、时间与防御 | 十维评分有硬约束；ETA/防御只做当前请求内的辅助判断 |
| 第五幕 | P21–P26 | 证据与边界 | 案例能对上链路，但真实效果仍需独立验证 |

### 2.3 时间预算

- 26 页正文 × 约 70–80 秒 ≈ 30–35 分钟；
- 开场/转场/案例留 3–5 分钟；
- 附录不计入正文时间，只作现场备用；
- 正文控制在 35–40 分钟，留 10–15 分钟问答。

## 5. 逐页设计剧本

> 每页字段：眉题 / 标题 / 核心结论 / 版式 / 主视觉 / 页面文字 / 底部横条 / 页脚 / 演讲备注 / 可能追问 / 来源 / 转场。

### P01 封面

- **眉题**：算法 · 阶段评审  
- **标题**：从一条轨迹到可解释判断  
- **副标题**：无人机态势判读算法的一次请求链路  
- **核心结论**：这不是模块清单，而是一条从观测到判断的链路。  
- **版式**：左侧标题区（55%），右侧一张抽象轨迹图（45%）；浅背景。  
- **主视觉**：生成一张简图：一条折线轨迹穿过三层同心圈，节点用青点，圈层用灰线，目标方向用橙色箭头；不要真实地名。  
- **页面文字**：标题 + 副标题 + 一行“阶段评审 · 2026-10”。  
- **底部横条**：无；封面保持干净。  
- **页脚**：项目名/日期。  
- **演讲备注**：今天不讲“所有模块”，而是跟着一次请求走完整条链；每个阶段只回答三个问题：输入什么、算什么、输出什么。  
- **来源**：高保真 md 第 1–2 章。  
- **转场**：先看算法实际能读到哪些数据。

### P02 输入、输出与边界

- **眉题**：算法 · 输入与边界  
- **标题**：算法从上游轨迹开始，不在这里重建感知  
- **核心结论**：输入决定可计算的结果；缺失数据必须显式标记。  
- **版式**：三栏卡片：输入 / 输出 / 非目标；每栏 3–4 行。  
- **主视觉**：无大图；三张卡片顶部用细色条（青/橙/灰）。  
- **页面文字**：
  - 输入：轨迹 `lngs/lats/ts/alts`、目标属性、四类身份源、地图、资源、修正/配置。
  - 输出：`analysisResult`、`targetAirspaceResults`、`targetIntentResults`、`exemptTargetResults`、`eventSuggestions`、诊断。
  - 非目标：不做雷达检测、不做视觉跟踪、不控制真实无人机、不做跨请求跟踪。
- **底部横条**：输入决定可计算的结果；缺失数据不能用默认值冒充。  
- **页脚**：来源：v3.2 协议 §9–§15；高保真 md 第 2–3 章。  
- **演讲备注**：强调“上游已经形成轨迹”；算法不处理原始回波/视频/射频。身份源是业务关联，不是传感器融合。  
- **可能追问**：为什么没有雷达检测？——本项目定位是态势判读，不是感知前端。  
- **来源**：高保真 md 第 1–3 章。  
- **转场**：这些输入进入一条固定链路。

### P03 端到端链路

- **眉题**：算法 · 主链路  
- **标题**：一次请求只做一次空间评估，后续模块共享事实  
- **核心结论**：主线是“共享事实”，不是模块堆叠。  
- **版式**：上方 8–10 个流程框（两行或一行），下方 3 个短点；整页以流程图为视觉主体。  
- **主视觉**：重绘高保真 md 图1：
  `源DTO → 网关/身份 → 轨迹解析 → SpatialContext → 豁免 → 聚类/队形 → 意图 → 威胁 → 防御 → DTO`
  每个框下方一行小字写“输出”。  
- **页面文字**：
  - 长窗口给意图/空间，短尾窗给聚类/队形。
  - 空间评估只做一次，意图/威胁/ETA/防御共享。
  - 三个时间量位置不同：边界时间在空间阶段，设施 ETA 在适配器，条件回退在引擎。
- **底部横条**：共享中间事实，才能保证同一请求里的结论一致。  
- **页脚**：来源：高保真 md 第 2 章；`engine.analyze` 调用链。  
- **演讲备注**：沿着箭头讲一遍，每到一个模块只说出“输入/输出/为什么需要”。不要在这一页讲参数。  
- **可能追问**：为什么先空间后豁免？——豁免需要空间事实（设施/计划），且豁免目标不进入聚类。  
- **来源**：高保真 md 第 2 章。  
- **转场**：先展开入口：轨迹怎样被清洗成可计算的事实。

### P04 轨迹预处理

- **眉题**：算法 · 轨迹预处理  
- **标题**：去重、双窗口、最低点数：先把轨迹变成可计算的事实  
- **核心结论**：长窗口给意图，短尾窗给聚类/队形，不能混用。

### P05 运动特征

- **眉题**：算法 · 运动特征  
- **标题**：速度、航向、直线度、跨度：四个量各有定义  
- **核心结论**：同名速度在不同模块不是同一个量。  
- **版式**：左侧 55% 轨迹折线图 + 四个标注；右侧 45% 定义表 + 两条公式。  
- **主视觉**：一条轨迹折线，标出相邻段速度、航向箭头、首尾距离/路径长度、最大点对跨度。  
- **页面文字**：
  - 段速度 = 距离/真实时间差；目标速度 = 最近 3 段平均。
  - 航向只在段长 ≥0.5 米时计算；航向变化取最近三次最大角差。
  - 直线度 = 首尾距离/路径长度；跨度 = 任意两点最大距离。
  - 聚类用中位数、I-24 用回归、空间用 12 点趋势；窗口不同。
- **正文公式**：
  - 式1：`v_k = d(p_{k−1}, p_k) / (t_k − t_{k−1})`；时间按秒、距离按米，间隔下限 0.001 秒。
  - 式2：`L = Σ d(p_{k−1}, p_k)`，`S = d(p_0, p_{n−1}) / L`；`L=0` 时 `S=0`。
  - 公式条放右侧定义表下方，符号解释一行：`d` 为相邻点距离，`L` 为路径长度，`S` 为直线度。
- **底部横条**：四个量各有窗口和几何定义，不能统称“系统速度”。  
- **页脚**：来源：高保真 md 第 4 章；式1–2。  
- **演讲备注**：用同一条轨迹说明“同一点集在不同窗口下产生不同特征”；公式只念符号和单位，不讲推导。  
- **可能追问**：为什么不用平均速度？——中位数抗单帧异常；目标速度用近期 3 段是规则需要。  
- **来源**：高保真 md 第 4 章。  
- **转场**：运动事实形成后，算法把轨迹放回地图，先做聚类。

### P06 聚类距离

- **眉题**：算法 · 聚类  
- **标题**：聚类不是固定 250 米，而是位置/方向/速度的可靠度复合距离  
- **核心结论**：位置尺度围绕 50 米基准自适应；方向/速度只在可靠时参与。  
- **版式**：左侧 55% 三特征 + 可靠度示意；右侧 45% 公式 + 归一化表；底部一条“100/101 米”实测。  
- **主视觉**：三列小图：位置、方向、速度；每个特征旁标“归一化/可靠度”。  
- **页面文字**：
  - 位置：两两距离在 50–100 米区间取均值，缺省 50 米。
  - 方向：20° 角差映射为 1.0；速度：1–15 m/s 均值，缺省 10。
  - 方向可靠度 = clip(稳健速度/2, 0, 1)；启停/大转向置 0；成对取 min。
  - 距离 = sqrt(d_pos² + (r_dir·d_dir)² + (r_speed·d_speed)²)。
- **正文公式**：
  - 式3：`r_ij = min(r_i, r_j)`；成对可靠度取两者较小值。
  - 式4：`D_ij = sqrt(d_pos² + (r_dir·d_dir)² + (r_speed·d_speed)²)`；位置项不乘可靠度，方向和速度项由 `r_ij` 降权。
  - 公式框放右侧，下方一行符号：`d_pos/d_dir/d_speed` 为归一化特征差，`r_dir/r_speed` 为成对可靠度。
- **底部横条**：5 架直线编队：100 米仍连通，101 米断开；尺度不是任意间距都自适应。  
- **页脚**：来源：高保真 md 第 5 章；`clusters_recognition.py`；式3–4。  
- **演讲备注**：先说“为什么不是固定半径”，再用 100/101 米的实测说明自适应尺度的边界；强调方向未知不会被当成方向冲突。公式只解释“哪一项被降权”，不展开推导。  
- **可能追问**：为什么 min_samples=1？——下一页解释。  
- **来源**：高保真 md 第 5 章。  
- **转场**：距离矩阵交给 DBSCAN；如果适配器失败，才走另一条回退。

### P07 DBSCAN 与回退

- **眉题**：算法 · 聚类  
- **标题**：min_samples=1 是连通分量；KD-tree 只在回退路径  
- **核心结论**：正常路径是可靠度 DBSCAN，不是 KD-tree。  
- **版式**：左侧 50% A–B–C 连通图 + 单例；右侧 50% 两路径流程 + 参数表。  
- **主视觉**：A 与 C 不直接相邻但通过 B 连通；孤立点作为单元素簇。  
- **页面文字**：
  - DBSCAN：eps=1.5、min_samples=1、precomputed；无噪声标签；孤立目标单元素簇。
  - 正常路径显式构造 N×N 距离矩阵，O(N²)，不是 O(N log N)。
  - 回退：适配器无分组时，250 米/50° 连通分组；>10 架用 KD-tree 找候选，再精确复核。
  - clusterId 是成员集合哈希，不是持续群体身份；无跨请求记忆。
- **正文公式**：DBSCAN 核心条件 `N_ε(p) ≥ min_samples`；当前 `min_samples=1`，任意点都是核心点，算法退化为在 `eps=1.5` 的归一化距离图上的连通分量（非编号式，放右侧参数表上方一行）。
- **底部横条**：KD-tree 是回退路径的邻居搜索加速，不是正常 DBSCAN 的加速器。  
- **页脚**：来源：高保真 md 第 5 章；`engine._clusters`、`test_cluster_distance_regression`。  
- **演讲备注**：先讲“min_samples=1 的语义”，再讲回退路径；强调 250 米不是主 DBSCAN 的 eps。  
- **可能追问**：为什么不保留噪声？——当前产品把孤立目标作为单机簇；文档不能同时说 min_samples=1 又有噪声语义。  
- **来源**：高保真 md 第 5 章。  
- **转场**：分组确定后，下一步是队形识别。

### P09 PointNet 结构与标准化

- **眉题**：算法 · 队形识别

- **演讲备注**：先讲“怎么测”，再讲三个数（13/100/200），最后讲“不能外推”；不要逐格念 24 个数字。  
- **可能追问**：为什么 200×240 比 200×120 慢？——240 点包含输入解析，意图窗口最多 121 个有效点；不是按点数线性增长。  
- **来源**：高保真 md 第 18 章。  
- **转场**：这些时延不是自然得到的，下面看四个优化及各自边界。

### P24 四个优化

- **眉题**：算法 · 工程优化  
- **标题**：四个优化，四个边界：向量化、跨度、KD-tree、请求内缓存  
- **核心结论**：组件收益有场景，不能把局部倍数说成整条请求加速。  
- **版式**：2×2 四张卡；每卡四行：做了什么 / 收益 / 边界 / 公式；底部浅青横条贯穿。  
- **主视觉**：四卡统一白底、顶部 6px 色条；左上向量化（青）、右上跨度（青）、左下 KD-tree（橙）、右下缓存（橙）；每卡右上角一个大数字。  
- **页面文字**：
  - **行为向量化**：100×120 中位 57.85→4.40 ms（13.16×）；200×120 114.29→9.39 ms（12.17×）；但特征定义与输出有差异——速度等级一致，部分数值/置信度/布尔值不同；属于方法变化，不是纯优化。
  - **跨度矩阵化**：120 点 4.64→0.23 ms（20.07×）；240 点 20.79→0.86 ms（24.09×）；最大绝对差 <2×10⁻⁹ 米；只属于跨度代码块，矩阵内存仍按 O(W²) 增长。
  - **KD-tree 回退**：分散 200 目标 18.21→1.71 ms（10.68×）；密集 200 目标 1.04→3.28 ms（0.32×，反而慢约 3 倍）；只在适配器无分组、目标数 >10 时启用，24 组成员集合全部一致。
  - **请求内缓存**：100 目标中位 459.78 ms（启用）对 548.18 ms（禁用），耗时比 1.19、下降 16.13%；底层特征计算 1700 次（启用）/ 3400 次（禁用），即每请求约 100 次对 200 次；不保证尾延迟，也不跨请求。
- **正文公式**：
  - 式17、式18（向量化卡）：`v_{i,k} = ‖P_{i,k+1}−P_{i,k}‖ / (t_{i,k+1}−t_{i,k})`；`a = (v̄_second − v̄_first) / v̄_first`。
  - 式19（缓存卡）：`S = median(T_ref)/median(T_opt)`，`G = 1 − 1/S`。
  - 式20（跨度卡）：`D = max_{i<j} d(p_i,p_j)`，`K = W(W−1)/2`；240 点对应 28,680 个点对。
  - 式21（KD-tree 卡）：`r_chord = 2R·sin(min(d/R, π)/2)`；`d` 为球面距离阈值，`R` 为地球半径。
- **底部横条**：优化有场景；组件收益不能外推为整条请求加速，向量化还伴随特征语义变化。  
- **页脚**：来源：高保真 md 第 18.2–18.7 节；`results.json`；式17–21。  
- **演讲备注**：每张卡 20 秒，只讲“做了什么、收益多少、边界在哪”；向量化卡主动说输出差异，KD-tree 卡主动说密集布局变慢。  
- **可能追问**：为什么 KD-tree 密集布局更慢？——几乎所有点都是邻居，建树和邻域处理开销抵消收益；且只在回退路径。  
- **来源**：高保真 md 第 18 章。  
- **转场**：这些边界共同说明：能说“实现一致”，不能说“现场有效”。

### P25 证据边界

- **眉题**：算法 · 证据边界  
- **标题**：哪些结论已经证明，哪些还没有

- **页面文字**：

  - 未证明：真实意图精确率/召回率、队形现场准确率、ETA 误差分布、并发/冷启动/长期尾延迟。
